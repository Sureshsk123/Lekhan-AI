# Enterprise GitHub Actions Pipeline

## Architecture
The CI/CD pipeline is orchestrated via active GitHub Actions (`backend-ci.yml`, `frontend-ci.yml`, `selenium.yml`) executing backend verification, frontend static build, and Selenium automation.

## Why `macos-latest`?
Android emulators require hardware acceleration (KVM/HAXM). While Linux runners can support nested virtualization, `macos-latest` runners provided by GitHub Actions come with native Hypervisor.framework support, allowing emulators to boot significantly faster and with less flakiness natively out-of-the-box.

## Execution Flow
1. **Checkout & Cache**: Restores Node dependencies and the heavy Android System Images (saving ~5 mins per run).
2. **Device Provisioning**: `setup-emulator.sh` and `wait-for-device.sh` boot the headless AVD and poll `sys.boot_completed` to ensure the device is completely stable before tests begin. Animations are disabled via ADB to reduce UI flakiness.
3. **Execution**: The `ExecutionManager` spins up the requested matrix.
4. **Publishing**: `publish-reports.sh` scrapes the `Report.json` generated by the Reporting Platform to populate the Markdown Job Summary natively in the GitHub UI. All Excel, HTML, and Screenshot artifacts are uploaded safely via `actions/upload-artifact`.

## Recovery Strategy
The `health-check.sh` validates that the ADB daemon has successfully connected to the `emulator-5554` port. If the daemon hangs (a common CI issue), it preemptively kills and restarts the ADB server before Appium launches.

## Matrix Scaling
The `mobile-nightly.yml` workflow uses a Matrix strategy `[31, 33, 34]`. This instructs GitHub actions to spin up 3 parallel macOS runners simultaneously, drastically reducing end-to-end execution time.
